# 리플 · 기획 / 화면 / 데이터 (1~3단계 확정본)

## 1. 범위 (Scope Planner)

확정한 결정: 모델 `gemini-2.5-flash` · 정답은 텍스트 입력 후 정규화/숫자 비교 · 복습은 체크만 하면 완료 · 이미지는 리사이즈·압축한 Base64로 저장.

| # | 기능 | 완료 조건 (사용자가 직접 확인) |
|---|---|---|
| F1 | 사진 → LaTeX → 유사 문제 3개 | 사진 1장 분석 시 원본 수식과 유사 문제 3개가 KaTeX로 표시 / 키 없으면 Mock 표시와 함께 동작 / 인식 실패·할당량 초과 시 안내와 재시도 / LaTeX 수정 가능 |
| F2 | 풀이·채점·기록 | 답 입력 시 정오와 해설 표시 / 새로고침 후 기록 유지 / 기록 화면에서 정답 수 확인 |
| F3 | 1·3·7일 복습 플래너 | 버튼 한 번에 +1/+3/+7일 3건 등록 / 홈에 오늘 복습 표시와 체크 / 중복 등록 불가 / 새로고침 후 유지 |

**v1 제외**: 유료 결제, 커뮤니티·공유, 튜터 질문, 로그인·서버 동기화, 푸시 알림, 그래프·도형·손글씨 인식, 수학 외 과목.

## 2. 화면 (Screen Designer) — 390px 기준

디자인: 오프화이트 `#FAF9F5` 배경, 잉크 `#3D3929` 본문, 테라코타 `#C96442` 포인트, `rounded-2xl` 카드와 1px 선(`#E8E6DC`), 제목은 세리프.

```
[홈]  헤더(리플 · 설정⚙)
      오늘의 복습 카드(날짜, 남은/완료, 진행바)   ← 첫 화면에서 바로 보임
      오늘 복습 목록(체크 / 탭하면 풀이 화면)
      FAB 📷(우하단, 하단탭 위)  ·  하단탭: 홈 / 플래너 / 기록
[스캔] 사진 영역 → 카메라·앨범 → 분석하기 → 결과 초안(KaTeX 미리보기, LaTeX·단원 수정) → 저장하고 풀어보기
[풀이] 원본 문제 + 유사 문제 3개(각각 KaTeX 카드, 답 입력, 채점, 해설) → 하단 고정 「복습 일정 등록」
[플래너] 날짜별 그룹(지남=빨강, 오늘=코랄), 체크 토글
[기록] 문제 목록, 정답 n/m, 삭제
[모달] API 키 입력(password), 발급 링크, 키 삭제
```

| 상태 | 위치 | 표시 |
|---|---|---|
| 빈 상태: 등록된 문제 없음 | 홈·기록 | 아이콘 + 「등록된 문제가 없어요」 + 스캔 버튼 |
| 빈 상태: 플래너 일정 없음 | 홈·플래너 | 「플래너 일정이 없어요」 + 등록 방법 |
| 에러: API 할당량 초과 | 스캔 | 안내 + 「다시 시도」 / 「Mock으로 계속」 |
| 에러: 사진 인식 불가 | 스캔 | 「다시 촬영」 안내 (Mock으로 덮지 않음) |
| 성공 | 풀이 | 초록 정답 박스 + 해설, 등록 후 「복습 일정이 등록되어 있어요」 |

## 3. 데이터 (Data Architect) — 키 `ripple:v1` 하나에 JSON 저장

개인정보(이름, 이메일, 위치)는 수집하지 않습니다. 저장 항목은 아래뿐입니다.

| 컬렉션.필드 | 타입 | 필수 | 기본값 / 검증 |
|---|---|---|---|
| settings.apiKey | string | N | `''` · 비면 Mock 모드 · trim |
| problems[].id | string | Y | `p_…` 자동 |
| problems[].createdAt | ISO string | Y | 생성 시각 |
| problems[].imageData | string(Base64 dataURL) | N | `null` · 긴 변 1024px, JPEG 0.7 |
| problems[].latex | string | **Y** | 공백 불가, 2000자 이내 |
| problems[].topic / tags | string / string[] | N | `미분류` / `[]` (40자, 최대 5개) |
| problems[].answer, explanation | string | N | `''` · 해설의 수식은 `$…$` |
| problems[].source | `gemini`\|`mock` | Y | |
| problems[].similar[] | {id, latex, answer, explanation} | Y | 1~3개, latex·answer 필수 |
| attempts[] | {id, problemId, itemId(`orig`\|`s1..s3`), userAnswer, correct, at} | Y | 문항당 1건, 재풀이 시 덮어쓰기 |
| reviews[] | {id, problemId, round(1\|2\|3), dueDate(`YYYY-MM-DD` 로컬), done, doneAt} | Y | 문제당 3건, 중복 등록 불가 |

**CRUD 규칙**: 생성은 스캔 저장 시 problem, 채점 시 attempt, 등록 버튼 시 reviews 3건. 조회는 앱 시작 시 한 번 load. 수정은 attempt 덮어쓰기, review 완료 토글, apiKey 변경. 삭제는 problem 삭제 시 attempts·reviews 연쇄 삭제. 손상 JSON은 빈 상태로 복구하고, 저장 용량 초과(QuotaExceeded)는 화면에 오류로 알립니다.

### 가상 데이터 3개

| id | topic | latex | 정답 | 복습일(기준 2026-10-05) |
|---|---|---|---|---|
| p_demo1 | 일차방정식 | `\frac{x+1}{2}=\frac{3}{4}` | -1/2 | 10-06, 10-08, 10-12 |
| p_demo2 | 제곱근 | `\sqrt{18}+\sqrt{8}` | 5\sqrt{2} | 10-06, 10-08, 10-12 |
| p_demo3 | 삼각비 | `\sin 30^\circ+\cos 60^\circ` | 1 | 10-06, 10-08, 10-12 |

### 비정상 입력 예시

| 입력 | 기대 동작 |
|---|---|
| latex가 빈 문자열/공백 | 저장 거부 「수식(LaTeX)이 비어 있습니다」 |
| 유사 문제 0개 | 저장 거부 |
| 답 입력 없이 채점 | 「답을 입력해 주세요」 |
| `dueDate` = `2026-2-30` | 형식 오류(`isDateStr` false) |
| 이미지가 15MB 초과 / 이미지 아닌 파일 | 업로드 거부 안내 |
| 저장된 JSON 손상 | 빈 상태로 시작 |
| 수식에 `<img onerror=…>` | 태그로 해석되지 않고 문자로 표시 |
